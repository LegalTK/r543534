## 1. Назначение и базовые принципы
Документ содержит исчерпывающее описание специфики режима HvH (Hack vs Hack) в Garry's Mod (Source Engine, x64). Назначение — предоставить ИИ полное контекстное понимание игровых механик, архитектуры чит-клиента и серверного окружения для эффективной помощи, в анализе и настройке скриптов.

> **Критически важно для ИИ:** HvH в Garry's Mod принципиально отличается от CS:GO / CS2.
> - Категорически **запрещено** переносить концепции CS:GO: лимиты десинка ~58–61°, анимационные слейвы, матрицу `m_flPoseParameter`, хитскан по телу (Baim), расчет Safe Points и Damage Tracking. В GMod эти механизмы работают по иным принципам (из-за сервера).

---

## 2. Игровое и серверное окружение

- **Античит:** Отсутствует. Читы официально разрешены правилами сервера — это фундамент режима.
- **Тикрейт:** Фиксированный **128 тиков** (`engine.TickInterval() ≈ 0.0078125` сек).
- **Плагин Only Head:** Урон на сервере регистрируется исключительно в хитбокс головы (`HITGROUP_HEAD`). Попадания в любые другие части тела полностью блокируются серверным плагином.
  - Следствие: попадание в голову = мгновенный ваншот.
  - Следствие для чита: Body Aim (Baim), расчет минимального урона (Min Damage), хитскан по телу и конечностям, а также логика Safe Point бесполезны и лишь тратят тики.
- **Прострелы (Wallbangs):** Запрещены / отключены серверной механикой (стены непробиваемы). Никаких алгоритмов трассировки `AutoWall` не требуется — стрельба ведется только при прямой видимости через стандартный `util.TraceLine`.
- **Физика и мувмент (Velocity):** Высокие настройки ускорения сервера (`sv_airaccelerate`, баннихоп, воздушные стрейфы). Скорость игроков быстро достигает сотен и тысяч юнитов в секунду (>100–1000+ u/s).
  - Следствие: обязательна **экстраполяция позиции цели** для компенсации скорости, задержки сети, фейклагов и интерполяции. Без экстраполяции аимбот стреляет хуже.

## 3. Правила и чек-лист для ИИ при разработке кода

Каждый раз при анализе, рефакторинге или написании нового кода для этого проекта ИИ обязан соблюдать следующие правила:

1. **Типизация аргументов модуля:** При вызове функций `ded.*`, взаимодействующих с сущностями (`GetSimulationTime`, `GetNetworkedEyeAngles` и др.), всегда передавать объект `Entity`, а не числовой `EntIndex()`, и проверять `IsValid(ent)`.
2. **Фокус на голове:** Никогда не добавлять логику сканирования конечностей, боди-аима или трекинга дамага — сервер все равно засчитает только хедшот.
3. **Управление `bSendPacket`:** Изменение состояния отправки пакетов должно производиться строго через `ded.SetBSendPacket(bool)` внутри контекста `CreateMove`.

## 4. Итоговая сводка

1. **Суть HvH-дуэли:** Защита = Anti-Aim (неограниченный фейк) + Fakelag (до 23 тиков). Атака = экстраполяция скорости (если требуется).
2. **Фейк не имеет лимитов:** Real может находиться на любой дельте относительно Fake (до 180°).
3. **Урон только в голову:** Ваншот хедсканом при прямой видимости, без прострелов и мультипойнтов.
4. **Чит-клиент:** Связка Lua + нативный C++ модуль `ded` (хуки движка, управление пакетами, отключение интерполяции).
